# 商品页面的声明适用范围校对

体验品商品资料采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/规格.json` | `id`、`series`、`outer`、`lining`、`batch` |
| `资料/依据.json` | `id`、`issued`、`text` |
| `资料/展位稿.json` | `id`、`channel`、`location`、`scope`、`part`、`text` |
| `资料/展示约束.json` | `id`、`location`、`together` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 工作台

```sh
npm run workbench          # 逐稿结论与已上线内容的处置
node workbench.js --json   # 同样的结果，带依据、原文范围和改写建议
```

| 模块 | 职责 |
| --- | --- |
| `claims.js` | 从文字读出对象、数值与单位、情形、比较对象、否定和限制，保留原文范围；`compareClaims` 指出改稿新增、删去和更正的事实 |
| `evidence.js` | 按录入日期叠加更正，得到每条依据的当前有效版本，并判断它覆盖哪些规格 |
| `review.js` | 结合依据、规格和渠道展示约束给出逐稿结论、系列汇总和改写建议 |
| `workbench.js` | 汇总停止、暂缓、保留的已上线文字及受影响规格 |

判定要点：

- 系列共用描述逐个规格核对；只有每个规格都有覆盖依据时才整体放行，一个规格的更正不会传播到整个系列。
- 对象、部位、批次、样条和时长限定必须与卖点同处可见；展示约束为主文单独出现的渠道，不能按原形式上架。
- 稿件单位与当前有效依据不一致时按更正处理，不做百分比与毫米之间的换算或批量替换。
- 量词没有对象线索（是材料性能还是成品效果）时给出 `review`，交审阅人确认具体证据，不自动放行。
- 短卡放不下必要限定时，建议缩小声明或取消该渠道投放；同一改稿在能完整展示限定的其他渠道仍可使用。
